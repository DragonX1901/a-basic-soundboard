Notes
-----
* This exercises the vulnerable sink directly in the parent process. The only step not
  driven is the IPC transport (AIChatContent:RequestAssets from a compromised privilegedabout
  content process); the parent handler delivers message data verbatim to #handleRequestAssets
  with no validation (verified by source review), so this faithfully reproduces the handler's
  behavior on attacker-supplied IPC data.
* file:// image-file oracle: attempted; the background-thumbnail capture hung in this headless
  environment (capture-queue/gfx artifact), so no clean positive local-file disclosure was
  landed here. The SSRF primitive is confirmed; the local-file oracle remains plausible per the
  code path but is unproven in this run.

UPDATE — FULL END-TO-END content->parent IPC confirmed
============================================================
Method: Marionette set_context("content"); navigate top-level to about:aichatcontent
(loads standalone in the privilegedabout process, <ai-chat-content> present). Then, as
ORDINARY PAGE SCRIPT (content principal, no chrome access, no user gesture), dispatch the
real DOM event the child actor forwards to the parent:

  const detail = { conversationId:"poc-e2e", messageId:"poc-e2e",
    items:[{ url:"http://127.0.0.1:8899/ignored",
             thumbnail:"http://127.0.0.1:8899/ipc-e2e-<ts>" }] };
  target.dispatchEvent(new CustomEvent("AIChatContent:RequestAssets",
                       { detail, bubbles:true, composed:true }));

The actor registers RequestAssets with wantUntrusted:true, so this untrusted (page-script)
event is delivered: AIChatContentChild.handleEvent -> sendAsyncMessage -> parent
AIChatContentParent.#handleRequestAssets -> captureThumbnail(thumbnail).

Dispatch result: {'dispatchedOn': 'ai-chat-content', 'url': 'about:aichatcontent', 'hasChatContent': True}
Parent SSRF hit: GET /ipc-e2e-1788954754 from 127.0.0.1     <-- PARENT fetched attacker URL

=> The complete content->parent boundary crossing via the real IPC path is confirmed on the
   official ASAN build, triggered by content-scope script with no user interaction.
   (Getting script into the privileged about:aichatcontent document still requires an
   injection/UXSS in that page or a compromised content process; page script is not
   normally attacker-controlled. Stated for honest severity scoping.)

UPDATE 2 — file:// local-file oracle does NOT work (honest negative)
============================================================
Tested captureThumbnail() with a valid 64x64 local PNG and a missing path:
  file:///home/user/poc/img64.png       -> result: null   (no thumbnail produced)
  file:///home/user/poc/missing-*.png   -> capture hung (no result)
Conclusion: file:// does not render to a thumbnail through this sink, so the
speculated LOCAL-FILE disclosure oracle is NOT exploitable via this path.
CONFIRMED impact is limited to: content-reachable PARENT-PROCESS SSRF over http/https
(incl. loopback/intranet), triggered end-to-end by content-scope script with no gesture.
